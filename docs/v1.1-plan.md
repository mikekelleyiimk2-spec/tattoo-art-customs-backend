# Tattoo Art Customs — v1.1 Plan: Shop Toolkit Expansion (owner-approved 2026-09-30)

Owner decision 2026-09-30: all nine toolkit features are **sandboxed to v1.1**
(post-launch update). Specs are done (see
[shop-toolkit-specs.md](./shop-toolkit-specs.md)); partial implementation
lives on branch `v1.1-shop-toolkit`; `main` is untouched and production has
nothing half-built. No public copy may promise toolkit items as live — all
customer-facing language stays "in development."

## Build order (when tokens allow)

1. **Cancellation auto-fill** — first because it's pure scheduling logic
   (no payments, no PII); hooks into the existing waitlist; immediate
   visible value for shops.
2. **Digital waivers + ID capture** — depends on: `ID_DOC_KEY` env var set
   (AES-256-GCM encryption for ID photos); fails closed without it. Waiver
   templates are shop-supplied; site provides the disclaimer copy only
   (we are not their lawyer).
3. **Aftercare autopilot + review machine** — depends on: (2) if waivers
   must exist before completion flows run (waiver required before
   `markCompleted` → aftercare scheduling). Depends on push/email
   delivery only.
4. **Slow-day blast + client reactivation** — independent of 1–3; needs
   past-client attribution data (see 5) to segment blasts well, but can
   ship on booking history alone.
5. **Booking attribution** — pure instrumentation; can go first in practice
   (tiny change), but ranked here because its value compounds once 4
   exists. Start stamping `attribution_source` as early as possible.
6. **No-show enforcement (PayPal-blocked)** — DO NOT BUILD charge execution
   until live PayPal credentials exist. Ship tables + policy engine +
   staff UI only; sweeps log-and-requeue in the meantime.
7. **Payment plans (PayPal-blocked)** — same gating as 6: plan creation and
   installment schedules are fine; `runPlanChargeSweep` must never attempt
   a charge without live credentials.

## Dependencies at a glance

- Live PayPal credentials → unlocks charge execution in 6 and 7.
- `ID_DOC_KEY` Render env var → unlocks ID capture in 2 (fails closed).
- Shops configuring waiver templates / aftercare templates → needed
  before 2 and 3 are useful in production.

## ⚠️ NEW — Platform-wide liability policy (attorney DRAFT)

Spec'd 2026-09-30 at owner request: a site+app-wide Terms of Service /
liability framework covering customers, designers, and shops —
marketplace-not-provider language, assumption of risk for tattoo services
booked through listed shops, limitation of liability, and how shop
waivers interact with platform terms. Full draft:
[liability-policy-DRAFT.md](./liability-policy-DRAFT.md).

**Flagged: SHIP WITH v1.0 IF POSSIBLE.** The site already takes money; the
existing ToS (`/terms`) covers marketplace mechanics only (pricing,
no-refunds, contact rules, payouts) and has **no liability language at
all**. The draft is explicitly marked "DRAFT — requires attorney review,
not final legal copy" and must go to a real attorney before publication.
Minimum viable v1.0 version: the limitation-of-liability + marketplace-not-provider
+ assumption-of-risk sections, reviewed by counsel, appended to `/terms`.

## What stays off the v1.0 list

- SMS on any channel (cost; push/email-first stands).
- Charge execution of any kind before live PayPal credentials.
- Public copy promising toolkit features as live.
